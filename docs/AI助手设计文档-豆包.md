# imb平台 任务（学习事件）与笔记关联设计方案

本文围绕imb平台“学习事件”核心场景，结合AI助手（智能秘书）能力，明确任务与笔记的关联逻辑，实现“任务发起→大模型辅助→笔记沉淀→闭环成长”的全流程设计，补充至原AI助手模块V2.0设计文档中，强化学习场景的功能闭环。

# 一、核心关联逻辑：以“学习事件”为锚点

笔记并非孤立存在，而是强绑定到“学习类事件”（如“学习基金投资”“掌握机器学习基础”等），通过大模型串联“任务信息收集→讨论迭代→笔记沉淀”全链路，形成三层关联体系，非学习类事件无需强制绑定笔记。

|层级|关联对象|核心关联方式|
|---|---|---|
|基础层|事件表(events) ↔ 笔记表(ai_notes)|通过event_id外键强关联，笔记归属唯一学习事件，支持1个事件关联多个版本笔记|
|能力层|大模型 ↔ 学习事件 + 笔记|大模型作为“智能秘书”，围绕学习事件目标，辅助完成笔记生成、迭代、优化全流程|
|流程层|任务进度 ↔ 笔记版本|笔记每一次更新关联学习事件的知识点完成状态，形成“进度-笔记”双向驱动闭环|
# 二、具体功能设计（结合大模型能力）

## 2.1 关联入口：从“学习事件”一键触达笔记

### 2.1.1 学习事件创建环节

用户创建学习类事件时，系统自动完成笔记初始化并提供AI助手入口，降低使用门槛：

1. 用户创建事件：填写标题（如“学习基金投资”）、选择类型为“学习事件”、设置挂载维度（如本月/本周）及目标描述；

2. 系统自动生成笔记：基于事件信息创建默认笔记草稿，标题格式为「[事件名] - 学习笔记（初稿）」，自动填充event_id关联字段，内容为空；

3. AI引导弹窗：创建成功后弹窗提示“是否召唤AI助手，为你收集[事件名]的基础资料并生成笔记初稿？”，支持一键触发大模型介入。

### 2.1.2 学习事件详情页

详情页固定展示“笔记模块”，整合编辑、AI辅助、版本管理功能，实现事件与笔记的联动操作：

- 笔记编辑区：支持Markdown实时编辑与预览，保留原文档的格式优化能力；

- AI辅助按钮：提供“收集资料”“总结要点”“答疑解惑”“优化笔记”四大核心功能按钮，一键调用大模型能力；

- 版本与进度面板：展示笔记历史版本（按时间排序，标注版本说明），同步关联学习事件的知识点完成进度，支持版本回溯与对比。

## 2.2 大模型辅助：让笔记成为“任务讨论的沉淀载体”

围绕学习事件目标，大模型以“智能秘书”身份与用户互动，将讨论过程、资料信息精准沉淀至笔记，避免内容碎片化。

### 2.2.1 资料收集：自动填充笔记初稿

用户触发“收集资料”按钮后，大模型基于学习事件目标，联动搜索服务与知识库，生成结构化笔记初稿：

### 2.2.2 互动讨论：对话内容一键沉淀至笔记

笔记编辑区内置“AI对话框”，用户可围绕学习事件实时与大模型讨论，讨论内容可选择性沉淀至笔记，实现“边聊边记”：

1. 实时对话：用户在对话框中提出疑问（如“货币基金收益为什么比定期存款高？”），大模型结合资料给出精准回答，支持多轮追问；

2. 内容沉淀：每轮对话结束后，系统提示“是否将本次对话加入笔记？”，用户确认后，对话内容按统一格式（标题+时间+问答内容）插入笔记对应章节；

3. 冗余过滤：支持用户手动编辑沉淀的对话内容，删除无效信息，确保笔记简洁性。

### 2.2.3 笔记优化：AI辅助结构化与查漏补缺

用户完成笔记初稿或补充内容后，可触发“优化笔记”功能，大模型从格式、内容、逻辑三方面优化，提升笔记质量：

- 格式优化：自动规整Markdown结构，统一标题层级（如一级标题用#、二级用##）、列表样式、代码块格式，确保排版美观；

- 内容补全：基于用户输入的零散内容，补充逻辑链条与关键信息，例如用户仅写“定投策略”，AI自动补充“定投的止盈/止损方法”“定投周期选择技巧”等关联知识点；

- 要点提炼：生成笔记核心摘要（100-200字），同步更新至学习事件的“具体实现方式”字段，让任务目标与进度更清晰；

- 语言润色：将口语化内容优化为书面语，保留用户核心观点，提升笔记专业性与可读性。

## 2.3 进度关联：笔记更新驱动任务推进

结合AI学习助手的“知识点闭环”逻辑，实现笔记与学习事件进度的双向联动，让学习过程可追踪、可沉淀：

### 2.3.1 知识点完成判定

大模型自动分析笔记内容，结合学习事件预设的知识点目标，判定知识点掌握状态：

1. 用户创建学习事件时，可预设知识点清单（如“基金投资”可预设“货币基金”“债券基金”“定投策略”3个知识点）；

2. 笔记更新后，大模型扫描内容，若覆盖某知识点的核心要点（定义、特点、实操方法），则判定该知识点“已掌握”，并弹窗提示“该知识点已掌握，是否推进到下一个知识点（如债券基金）？”；

3. 若笔记内容残缺（仅提及知识点名称，无核心信息），则提示“当前知识点内容不完整，是否需要AI辅助补充核心要点？”。

### 2.3.2 笔记版本与进度绑定

- 版本快照：每完成一个知识点，系统自动为笔记生成“版本快照”，命名格式为「[事件名] - 知识点X（名称）- 完成版」，记录版本更新时间与对应知识点状态；

- 进度同步：知识点完成状态同步更新至学习项目表（learning_projects），自动调整current_node为下一个知识点ID，更新任务完成率（如完成3个知识点中的1个，完成率33%）；

- 回滚支持：若用户需修改已完成知识点的笔记内容，可回溯对应版本，修改后系统重新判定知识点状态，同步更新任务进度。

### 2.3.3 成长回顾与可视化

系统基于笔记更新轨迹与任务进度，生成学习成长报告，强化用户成就感：

- 轨迹展示：在“历史回顾视图”中，按“学习事件”维度展示笔记更新时间线，标注每版笔记对应的知识点完成情况；

- 成长曲线：自动生成“学习成长曲线”，可视化展示“时间-笔记更新次数-知识点完成数量”的关联关系，例如“2026.01.01-2026.01.10，你围绕‘基金投资’共更新笔记5次，完成3个知识点，平均每3天掌握1个知识点”；

- 沉淀复用：将完成的笔记自动归类至个人知识库，支持按事件、知识点标签检索，便于后续复习与复用。

# 三、与原系统的适配说明

## 3.1 数据模型适配

基于原ai_notes表扩展字段，无需新增数据表，降低开发成本：

- 保留原表核心字段（id、task_id、conversation_id等）；

- 新增字段：event_id（BIGINT，FK关联events表id，非空）、knowledge_node（JSON，存储对应知识点ID与完成状态）、version_desc（VARCHAR(255)，版本说明，如“知识点1（货币基金）完成版”）。

## 3.2 API适配

在原笔记管理API基础上补充2个接口，支持事件与笔记的联动：

1. 创建学习事件同步生成笔记接口：POST /api/ai/events/{eventId}/notes/init，自动生成关联笔记草稿；

2. 笔记更新同步进度接口：PATCH /api/ai/notes/{noteId}/sync-progress，笔记更新后同步触发知识点状态判定与任务进度更新。

## 3.3 前端适配

在原事件详情页、笔记编辑页基础上调整布局：

- 事件详情页：新增“笔记模块”，整合编辑、AI辅助、版本管理功能；

- 笔记编辑页：新增“事件关联”标识，显示对应学习事件名称与进度，提供一键跳转至事件详情页的入口；

- 新增“学习成长视图”，可视化展示笔记与任务进度的关联轨迹。

# 四、核心价值总结

1. 闭环化学习：打通“任务发起-资料收集-讨论迭代-笔记沉淀-进度追踪”全链路，避免学习过程碎片化；

2. 智能化提效：通过大模型辅助减少笔记创作、优化的时间成本，让用户专注于知识吸收与实践；

3. 个性化沉淀：笔记与学习事件强绑定，形成个人专属学习知识库，支持长期复用与回顾；

4. 可视化成长：通过笔记轨迹与成长曲线，让学习成果可量化、可感知，提升用户学习动力。
