# 需求规格说明书 (PRD) - imb (I'm Boss)

**项目名称**：imb (i'm boss)
**版本号**：V1.0
**文档日期**：2026年1月9日

## 1. 项目概述 (Overview)

### 1.1 产品背景
imb 是 "i'm boss" 的缩写。这是一个个人效率与学习辅助平台，旨在帮助用户像“老板”一样管理自己的每日工作与学习任务。用户作为决策者（Boss），系统作为执行助手（结合AI能力），协助用户完成学习规划、进度追踪及信息整合。

### 1.2 核心价值
- **全维度管理**：从日、周、月、年不同维度管理生活与学习。
- **AI 赋能学习**：利用 AI 的搜索与整合能力，自动生成学习大纲、拆解任务并驱动学习进度。
- **像 Boss 一样批阅**：用户只需设定目标（如“我要学投资”），系统负责拆解和辅助，用户最后进行验收和“批阅”。

## 3. 功能需求 (Functional Requirements)

### 3.1 仪表盘与视图 (Dashboard & Views)

#### 3.1.1 每日视图 (默认主页)
- **展示内容**：当前日期需要完成的所有“事件”。
- **操作**：
  - 能够勾选完成事件。
  - 能够快速添加今日事件。
- **导航**：类似日历，可以左右翻页查看过去或未来的“每日待办”。

#### 3.1.2 多维度视图 (周/月/年)
- **交互**：点击“周”、“月”或“年”标签切换视图。
- **展示逻辑**：
  - **当前维度的特定任务**：例如“本周必须完成的总结”。
  - **低维度任务聚合**：
    - 针对重复性高的日常任务（如“每日背单词”），在周/月视图中不罗列每一条，而是**合并显示**。
    - **显示方式**：显示统计数据（例如：“本周背单词：已完成 5/7 次”）。

#### 3.1.3 历史回顾视图
- **功能**：展示过去一段时间内事件的完成情况（统计图表或列表）。

### 3.2 事件管理 (Event Management)

#### 3.2.1 事件基础属性
- **名称**：事件标题。
- **重要度**：优先级标记（高/中/低）。
- **具体实现方式**：描述如何做。
- **提醒时间**：具体的推送/通知时间点。
- **状态**：未开始、进行中、已完成、等待中。
- **挂载维度**：可挂载在 具体某天、某周、某月 或 某年。

#### 3.2.2 事件类型及特殊逻辑
1.  **日常事件 (Routine)**
    - *示例*：读书、弹琴。
    - *特殊元素*：**周期规则** (如：每周一到周五，每月15日，每年X日)。
2.  **提醒事件 (One-time)**
    - *示例*：某天参加会议。
    - *特殊元素*：支持设置**多个**具体日期和时间点提醒。
3.  **学习事件 (Learning)**
    - *示例*：学习投资。
    - *特殊元素*：关联**学习知识点**、关联**Markdown笔记**。

#### 3.2.3 事件创建方式
1.  **手动创建**：填写表单录入。
2.  **AI 智能生成**：
    - 输入：图片、链接或一段文字。
    - 处理：AI 分析内容，自动提取关键信息生成“每日代办事件”。

### 3.3 笔记功能 (Notes)
- **关联性**：笔记强关联于“学习事件”。
- **格式**：支持 **Markdown** 语法（标题、代码块、列表、加粗等）。
- **流程**：
  - 每次学习完成后，系统引导用户进行阶段性总结。
  - 总结内容自动归档为该学习事件的笔记。

### 3.4 AI 学习助手 (AI Agent)

这是本系统的核心差异化功能，工作流如下：

1.  **构建大纲**：
    - 用户输入学习目标（如“学习Spring Boot”）。
    - AI 搜索网络并分析，构建一套包含多个“知识点”的学习大纲。
2.  **学习引导**：
    - 系统锁定第一个知识点，提醒用户开始学习。
3.  **笔记与反馈**：
    - 用户学习过程中/结束后，在系统内记录 Markdown 笔记。
    - AI 分析笔记内容，确认当前知识点是否掌握。
4.  **动态推进**：
    - 当用户手动确认完成（或 AI 判定完成）当前知识点。
    - 系统自动推进到下一个知识点，并发出提醒。
    - 循环直到所有知识点完成。

## 4. 数据模型设计 (Data Models - 简易版)

为了配合你的数据库选型，以下是核心表结构的建议：

### 4.1 事件表 (events)
| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | BIGINT | 主键 |
| title | VARCHAR | 事件名称 |
| type | ENUM | 类型：ROUTINE(日常), REMINDER(提醒), LEARNING(学习) |
| priority | INT | 重要度 |
| status | ENUM | 状态：TODO, DONE, WAITING |
| dimension | ENUM | 维度：DAY, WEEK, MONTH, YEAR |
| config_json | **JSON** | **核心设计**：存储不同类型的特殊字段（如重复周期规则、提醒时间列表） |
| created_at | DATETIME | 创建时间 |

### 4.2 学习项目表 (learning_projects)
*用于扩展“学习事件”的详情*
| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | BIGINT | 主键 |
| event_id | BIGINT | 关联 events 表 |
| outline_json | **JSON** | AI生成的学习大纲结构树 |
| current_node | VARCHAR | 当前正在进行的知识点ID |

### 4.3 笔记表 (notes)
| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | BIGINT | 主键 |
| event_id | BIGINT | 关联 events 表 |
| content | TEXT/LONGTEXT | Markdown 原始内容 |
| created_at | DATETIME | |

## 5. 交互设计细节 (UX Design)

### 5.1 周的定义
- 系统强制设定：**周一为一周的开始，周日为一周的结束**。

### 5.2 智能聚合显示
- 当用户点击“月视图”时：
  - 不要列出 30 个“背单词”任务。
  - 显示为一个进度条卡片：“背单词 (本月进度: 20/30)”。
  - 点击卡片可展开查看具体的每日完成情况。

### 5.3 导入解析
- 提供一个全局“+”号。
- 支持粘贴文本、URL 或上传图片。
- 后台调用 AI 接口解析后，弹窗让用户确认：“我识别到你想添加一个会议提醒，时间是...，确认吗？”

## 6. 开发路线图建议 (Roadmap)

1.  **阶段一 (MVP - 最小可行性产品)**：
    - 搭建 Spring Boot + MySQL + React 环境。
    - 实现基础的“事件”增删改查（手动创建）。
    - 实现日视图和简单的日历翻页。
    - 集成 Markdown 编辑器。

2.  **阶段二 (AI 接入)**：
    - 接入 OpenAI/DeepSeek 等大模型 API。
    - 实现“输入目标 -> 生成学习大纲”的功能。
    - 实现非结构化数据（文本/链接）导入生成事件。

3.  **阶段三 (视图优化)**：
    - 实现周/月/年的聚合统计逻辑。
    - 优化前端 UI，达到“Boss”级别的视觉体验。
